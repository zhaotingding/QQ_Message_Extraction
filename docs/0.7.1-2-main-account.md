# 0.7.1-2大号：换号与数据保留

基点：`v0.7.0`（`e3491c6`）。分支：`feature/0.7.1-2-main-account`。
界面和 Git 标签使用 `0.7.1-2大号`；Python 包版本采用合法格式 `0.7.1.post2`。
本分支仍使用 NapCat。LLBot、官方机器人分支后续从相同基点创建。

## 使用

1. 在旧界面停止消息服务，再关闭旧界面，重新打开项目启动器。
2. 在“设置 → 协议端”填写大号的 QQ 号并保存。首次换号请在 NapCat 管理页切换到大号并扫码；
   本程序不会为了换号结束其他普通 QQ 客户端。已经登录其他账号时，自动登录会明确拒绝操作。
3. 启动消息服务，点击“自动登录”。有大号缓存凭证时只使用大号；无凭证时提示扫码，
   不回退登录小号。收到目标账号的新群消息后，才确认消息接收有效。
4. 检查“设置”中的群选择：保留原有选择，不会因换号擅自扩大采集范围。
   如需采集大号的新群，请刷新群列表并调整勾选。

“强制重启”只通过 NapCat 的本机管理接口恢复目标账号的登录进程。
管理接口不可用或账号不一致时明确报错，不回退调用结束所有 QQ 的旧脚本。

## 数据规则

- 继续使用现有数据库，保留小号消息、图片 OCR/解析、摘要及历史账目。
- 首次迁移前自动在数据库旁生成 `*.pre-account-*.bak`，使用 SQLite 在线备份，包含 WAL 中已提交的数据。
- 迁移保留原消息行 ID，账单 `source_ids`、图片结果、历史摘要不重新生成。
- 只根据消息原始 JSON 的 `self_id` 回填历史接收账号；缺失、截断或无效的记录保持未知。
- 每个账号分别记录收到的消息 ID；不同账号相同 ID 但内容不同的消息不会相互覆盖或被误丢弃。
- 跨账号只有消息 ID、群、时间、发送者、消息类型、正文一致，且媒体内容也可确认一致时，
  才共用一条正文及图片结果；分别保留接收记录。无法确认同一条消息时宁可保留，不按相似文本删消息。
- 实时消息增加“接收账号”列，共同群显示多个历史接收账号。历史消息仍参与原有查询与摘要范围。
- 消费明细仍按模型 API 配置统计；换 QQ 账号不会删除或重算历史费用。

Git 只管理代码，不隔离数据库、偏好和 QQ 登录状态。不要同时运行不同分支指向同一数据库。
以后试验其他分支时，应使用单独的数据副本和配置；不要把旧备份覆盖到已经收到新消息的数据库上。

## 本次验证

- 15 组离线回归覆盖数据迁移、账号校验、模拟登录、接收接口、摘要、图片与界面。
- 用真实数据库备份的副本迁移：13,363 条消息、29 份摘要、193 条 API 请求、10 个群，
  以及其他原表逐字段一致；完整性检查通过，再次打开幂等。
- 其中 11,607 条消息有原始接收账号证据，1,756 条保持历史未知。
- 本次未迁移正在使用的数据库、未切换真实 QQ 登录、未调用付费模型 API、未修改网络。
  数据库将在用户以新版本启动服务时执行迁移；大号实际登录与长期稳定性仍需运行验证。
