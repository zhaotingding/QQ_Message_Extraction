# 配置优先级与凭据隔离

适用：0.9.9；验证日期与范围见各条记录。路径相对仓库根目录，`data/` 为本地忽略证据，不能假设每个克隆都含原件。

## 主配置和偏好

`config.load()` 优先选显式路径；未传路径时，有 `.ui/config.local.yaml` 就使用该文件，否则使用共享 `config.yaml`。所选文件与内置默认值合并，再从 `MSGX_PREFS` 叠加本机偏好。本机主配置是完整替代，不与共享文件逐字段叠加；创建时复制完整共享文件再编辑，避免遗漏 `api` 后退回内置旧模式。损坏的本机文件报错，不静默回退。GUI 启动服务时传偏好路径，直接CLI不应假定使用当前窗口偏好。账号、群号、路径、正则和多行提示词需保持原值及类型；省略目标字数与显式设置默认值不能混同。偏好保存采用原子替换。

2026-10-20在独立Conda环境/Python3.13.16中运行 `tests/test_yaml_config.py`，12项通过，覆盖本机完整替代、显式路径优先、损坏配置报错及偏好叠加；证据为 `data/diagnostics/manual-install-20261020/test-results.yaml` 和同目录原始日志。无参数EXE、GUI和后台仍复用同一加载入口，不新增第二套配置加载逻辑；本次未启动生产实例或恢复真实资料。

程序不自动加载 `.env`；旧模式仅读取已存在的系统 `api_key_env`。不把真实密钥写入共享 YAML 或示例。迁移仍由旧 JSON GUI 写入的偏好前，先结束其写入，避免覆盖最后一次保存；不能据历史迁移经验擅自关闭当前窗口。

## 保留与恢复资料时读取

- 原位置升级保留个人偏好、图标、可选本机主配置和实际数据目录；`MSGX_ROOT` 决定默认配置与资料根，`--config` 只替换主配置文件，不自动改变资料根或相对路径基准。
- 图片 `media_path` 和报告 `report_path` 可为绝对路径；打开原图/HTML及媒体保留清理直接使用库内路径。复制数据库到新目录可能仍访问或删除原目录文件，不能作为隔离测试副本。跨根迁移要单独处理路径与一致性备份，本次手动升级路线在原数据位置验证。
- Windows凭据标识不包含仓库或Conda目录；同用户新克隆可能继续读到已有API密钥。GUI不自动启动服务，但接收服务启动后会检查摘要补期/恢复、重新下载待处理图片，并运行保留清理；恢复后的首次启动须让用户知晓可能的外部请求与费用。
- 上述为2026-10-20源码静态核对：`config.py`、`credentials.py`、`media.py`、`summary_store.py`、`message_store.py`、`pipeline.py`、`summary_scheduler.py`。未读取真实凭据或数据库，未验证任意跨目录迁移成功。

## API配置和保存反馈

相同地址的不同profile、同一profile的不同完整地址均隔离密钥。凭据保存失败而普通设置已成功时，只报告实际结果；不能清空仍未保存的密钥，也不能以“已配置”替代本次保存成功提示。

完整地址指经 `api_settings.endpoint()` 规范化后的地址：去除两端空白，主机名按IDNA转换并小写，移除默认443端口和路径末尾斜杠，保留路径大小写。`credentials._target()` 用该地址和profile生成凭据标识；空profile与 `openai` 保持既有兼容标识。调整规范化或标识规则前核对已有凭据归属，避免使原密钥不可读或串用。此处为2026-10-15源码静态核对，未实写Windows凭据。
