# 摘要恢复与费用

负责周期摘要、手动主题报、请求恢复与用量账本。主题报和桌面原币支出按 2026-11-23 的开发分支核对。

| 当前问题 | 先核对的项目状态 |
|---|---|
| 新生成或材料/字数调整 | `summarize.py` 的自然周期、来源材料、已保存档案及本次输出/推理预算 |
| 手动生成或增量修订主题报 | 先查日报相关段落及其指纹，再区分已发布正文、本次草稿和可恢复批次。见[手动主题报](references/recovery.md#手动主题报)。 |
| 首页累计、支出趋势或原币对账 | 先查请求发起时间、成功状态、计价币种及原币金额。主页和费用页共用 [原币支出口径](references/recovery.md#原币支出)。 |
| 响应中断或补生成 | `summary_scheduler.py`、`summary_store.py` 与 `llm.py` 的原任务修订、response ID、终态与快照 |
| 成稿/费用不一致 | 成稿保存阶段、`usage_store.py` 和 `accounted`，区分远端生成与本地恢复 |
| 提示词自动更新 | `prompt_evolution.py` 的已完成日报、动态版本与在途请求，不直接改个人基础提示词 |

- 当前生成入口为 `Summarizer.run_period`；北京自然周期左闭右开，报告按内容窗口排序，生成时间只作元数据。旧手动摘要HTTP入口继续拒绝，不能为恢复故障复活旧生成路径。
- 优先复用成稿、已完成分块和后台响应。有response_id且结果仍未明时取回原任务，沿用材料及原API/费率快照；无ID且提交结果未知时保持blocked，重新提交需要具体授权。已确认失败的补生成依现有调度分支处理。
- 用量账本与 `accounted` 同事务提交；成稿保存失败继续本地恢复，不能再次生成或重复记账。补生成核对任务最新修订并唤醒原调度，不另起并行循环。
- 自更新只提炼近期已完成、按自然日去重的日报，保存有来源的动态观察版本；个人基础提示词保留。动态文本作为低权限材料进入下一任务，在途请求保持原快照；未知提交不按周期自动重发。
- 官方OpenAI的Flex费率输入以Standard单价为基准，按响应实际档位估算；未返回时标明请求档位推算，未知用量不算免费。余额覆盖日期与北京时间账本一致。
- 仅按项目已有获批策略，在官方 Flex 明确容量拒绝时转 Standard，不把普通限流或未知提交当容量不足；实际提交档位与响应ID一起持久化，恢复时不能仍按原Flex半价估算。通用偏好不能擅自改写旧任务策略。
- 新任务输出预算须同时容纳档案指定的推理与正文，并受该档案/模型容量及材料余量限制；不机械复制某次实验的 Token 数或降低用户已选推理强度。已有任务沿原预算、材料与协议快照恢复；项目 1.0.5 的预算变更与一次真实验收见参考“调度与提交”。
- 排查失败、修改请求/调度/费用时读取 [恢复链路和计费证据](references/recovery.md)，区分已提交、可取回、确定失败及结果未知，再决定后续动作。历史经验不是发送聊天或增加费用的授权。
- 调整摘要筛选与提示词时，读取同一参考资料的“提示词与报告内容评估”一节；区分报告内容统计、离线兼容性和真实生成效果，不为评估自动重跑付费日报。
