# 群发与退群操作

适用现有群发、退群与清理链路；用户约定与隔离证据更新于 2026-11-08，2026-11-16 整理前后端边界。本次未执行真实 QQ 操作。

- 首先遵循项目 AGENTS.md 置顶的用户群发规则；开发授权不等于对真实正文和接收群的发送确认。
- 按“预览 → 用户逐群勾选并明确确认 → 逐群执行 → 结果读回”处理，复用 `group_actions.py` 与 `group_action_store.py`；Electron/Tk 只呈现并提交已有契约，不在 UI 另写直接 QQ 发送路径。
- 查询中的空统计名单代表全部，群发中则禁止；不得把读取场景的空名单语义带入发送。
- 群发接收群由用户**逐群勾选**，默认一个都不勾；界面把勾选的群号随确认提交，服务端只接受预览名单的**子集**，空选与名单外的群一律拒绝。偏好的 `broadcast_groups` 只用于下次预填，不能替代本次确认。
- 固定已验证账号的协议连接；确认只接受服务端快照令牌，客户端只能从中挑选子集，不能替换正文或新增群名。账号、成员范围、保存名单或连接变化时停止，重新预览。
- 失败、超时未知和未提交分别保留；未知操作不自动重发，重启只恢复结果展示。**单群被协议拒绝只让该群失败并继续后面的群**（不重试该群）；只有结果未知、连接或名单变化才停止整批。界面结束文案只给计数，失败原因放逐群表格。退群明确成功前不删消息，`is_dismiss` 固定为 false。
- 退群清理只操作消息及关联记录，保留已生成摘要/报告/批注/费用和原图文件；不承诺已删消息的孤立图片仍会被原保留期逻辑发现。处理中的同群图片阻止退群，排队旧消息不能回填。
- 先判断修改的是预览范围、确认快照、执行/恢复还是清理，再读 [操作契约与验证入口](references/operations.md)对应条目。验收覆盖当前客户端的勾选名单与服务端拒绝空选，不能仅靠按钮置灰或旧 Tk 测试证明 Electron 安全。真实发送或退群仍须针对实际内容/对象获得确认，禁止用生产工作群验收。
