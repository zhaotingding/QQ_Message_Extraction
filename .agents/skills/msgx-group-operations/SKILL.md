# 群发与退群操作

适用：1.0.3；用户约定与隔离证据更新：2026-11-03。真实 QQ 操作未在开发回归中执行。

- 首先遵循项目 AGENTS.md 置顶的用户群发规则；开发授权不等于对真实正文和接收群的发送确认。
- 复用 `group_actions.py` 的预览→一次确认→逐群执行及 `group_action_store.py` 流水，不在 UI 另写直接 QQ 发送路径。
- 查询中的空统计名单代表全部，群发中则禁止；不得把读取场景的空名单语义带入发送。
- 固定已验证账号的协议连接；确认只接受服务端快照令牌，不接受客户端替换名单/正文。账号、成员范围、保存名单或连接变化时停止，重新预览。
- 失败、超时未知和未提交分别保留；未知操作不自动重发，重启只恢复结果展示。退群明确成功前不删消息，`is_dismiss` 固定为 false。
- 退群清理只操作消息及关联记录，保留已生成摘要/报告/批注/费用和原图文件；不承诺已删消息的孤立图片仍会被原保留期逻辑发现。处理中的同群图片阻止退群，排队旧消息不能回填。
- 修改上述边界前读取 [操作契约与验证入口](references/operations.md)；真实发送或退群仍须针对实际内容/对象获得确认，禁止用生产工作群验收。
