# 图片分析的调用边界

适用：1.0.2；检查日期：2026-10-31。完整41组隔离回归通过，含10项规则、26项图片及25项实时Tk；真实图片语义准确率未评测。

- `image_policy.py` 提供22项报告主题初值及集中匹配实现，个人 `image_analysis.keyword_rules` 优先；缺省才初始化，显式[]停分。每条可改literal/regex、score0～100、enabled、max_hits1～10、repeat_factor0～1。OCR未命中不因字数或上下文单独加分；总分封顶100，广告/表情过滤仍优先。
- `ui/image_rules.py` 编辑与试匹配不调用API；保存包含当前表单，只局部更新规则，不提交其他图片草稿。校验非法正则、空匹配、分数及次数边界；pattern首尾空白保留。初值恢复是显式操作，不因升级发生。
- `image_analysis.py` 独立串行处理本地初筛及自动候选；`image_analysis_store.py` 复用 Store 连接保存分数、理由、claim 与结果未知状态。字段迁移不重跑旧图片下载。
- 达阈值首次标记时保存 `auto_ready_at=当前时间+900秒` 与waiting；重开不重置等待时间，网络claim只发生在到期后。规则版本只重筛近期旧分数，不能重跑下载/OCR或重发unknown。
- 规则编译缓存，稳定63位指纹作为screen_version；指纹无大小顺序，按不同值判断重筛。旧规则分支逐批有界，扫空缓存包含指纹/范围/过滤；新图走pending，自动候选必须匹配当前版本，防止未重筛旧高分上传。用查询次数及EXPLAIN验证，不能固定优化器索引名。
- 分析时补收原图同群前3分钟至后15分钟的有界文字；高流量群抽样并保留配文。成功语义优先用于预览及摘要，原始`ocr_text`保留，不能将“替换OCR展示”实现为销毁原始证据。
- 默认关闭自动上传，阈值70、每天20张、1元本地估算上限，近7天候选。预算不是供应商硬封顶；单次预留采用有界输入和实际图片输出上限，按可回退Standard的费用预留，未知用量暂停当天自动队列。
- 账号依据接收凭据，当前群依据 `account_group_snapshots`；多账号共收同一父消息时，上下文必须使用当前接收账号，不能只用父行最早的 received_by。
- 同图语义仅在相同群、相同配文及近邻时间内复用，防止将另一段讨论的上下文解释误贴过来。已有 OCR 则可按图片摘要复用。
- 已保存的 `image_api_profile` 与 `active_api_profile` 分别决定图片和摘要；LLM.snapshot(role="image") 为图片冻结配置，Windows凭据仍按 profile 与基础地址隔离。配置中未在界面展示的参数须保留，不能保存时被默认值覆盖。
- `自动图片理解` 与 `提示词更新` 都进入现有用量账本和消费页面；图片自动队列的 running/unknown 不因重开而变回未尝试。
- `vision_requested_at` 在真实图片API的本地检查之后、提交之前标记；绿底表示有调用记录，纯OCR/等待不标绿，旧成功语义也可强调。图片none意图在Responses转换中保留；不完整输出不作为成功语义，也不自动追加请求。
- 相关隔离覆盖：`tests/test_image_rules.py`、`test_image_analysis.py`、`test_automation_gui.py`、`test_realtime_gui.py`与模型测试；本轮证据见本地忽略目录 `data/diagnostics/v1.0.2/`。不把模拟API或规则案例当作真实付费识别准确率。

## 主题来源与验证边界

2026-10-31只读最近14个按自然日去重的日报和3份周报；权重只由日报命中天数计算，周报复用日报，只用于复核。基础分为`16+min(16,2×命中日报天数)`。来源、命中天数及选择说明在本地忽略目录`data/diagnostics/v1.0.1/关键词选择.md`；只将可共享主题/规则入库，不提交私人报告或原文。

上述是1.0.1初值依据，1.0.2起用户可编辑并持久保存；后续报告变化不会自动改写个人规则，不能将来源统计当作真实图片准确率评测。修改规则时验证重复封顶、英文边界、显式空列表、保存重开、版本重筛及未知不重发。
