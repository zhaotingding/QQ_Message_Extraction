# 图片初筛与分析

负责“下载/OCR → 本地初筛 → 等待上下文 → 获准 API 请求 → 语义落库 → 摘要取材”，不是单一图片 API 包装。原规则与隔离证据始于 1.0.2；2026-11-16 整理职责，未重跑识别。

- 先按失败阶段定位 `image_policy.py`、`image_analysis.py`、`image_analysis_store.py` 或模型请求层；设置改动核对当前 Electron `settings_api.py`，旧 `ui/image_rules.py` 仅作 Tk 对照。局部规则编辑不因保存就触发网络验证。

- OCR使用个人可编辑主题词/正则与分数；初始报告主题仅作缺省值，显式空列表停分。规则变更按稳定指纹逐批重筛，不重发已提交或未知请求；达阈值仍等待15分钟收原图前后有界文字。
- 图片使用独立已保存 API 配置，缺省跟随摘要；快照冻结密钥归属、模型和费率。新任务尊重该配置的较低输出上限，不能复用摘要密钥或无声回退到另一个服务。
- 自动上传须显式启用；候选受当前账号成员快照、统计群、分数、材料日期、每日次数和估算预算约束。次数与未知状态持久化；请求前先 claim，关闭或中断后不盲目重发。
- 图片语义成功落库后才自动纳入摘要；摘要只用已保存材料，不在阅读或生成时补调用图片 API。缓存命中、写入和同图语义复用是不同事实。
- 实时绿色表示发起过图片API或已有成功语义，不代表生成成功；纯OCR/等待不标绿。图片请求不思考意图须保留，incomplete不能作为成功语义或触发自动重跑。
- 改筛选、候选或计费控制前，读取 [调用边界与验证](references/screening.md)相应阶段；通用供应商能力沿用可用的个人 llm-api-integration，图片角色快照与业务限额仍由项目实现决定。
- 用合成图片、临时库和模型替身验证受影响阶段，区分规则命中、请求发生、完整语义保存及最终摘要采用；历史关键词命中率不证明识别质量。真实上传图片需当前任务的具体授权。
